# Python dependencies for the foxBMS 2 ASPICE corpus tooling
#
# WHY THIS FILE EXISTS
# --------------------
# `docs/artifacts/tools/corpus.py` exits with status 2 and the single line
#
#     ERROR: jsonschema library required
#
# (the preflight now prints several lines after that first line rather than a
# parenthetical command that does not work on a macOS-managed Python; see
# PREFLIGHT-DEP-A1 in corpus.py and docs/artifacts/tools/bootstrap.sh)
#
# if `jsonschema` cannot be imported, and `make_review_packets.py` reports its
# schema checks as "validator unavailable" rather than failing. Neither
# dependency was declared anywhere in this repository until now, and neither is
# declared by any packaging manifest, because there is no packaging manifest:
# the corpus tooling is a set of scripts run directly with the system `python3`.
#
# The consequence is that the acceptance suite does not degrade, it DISAPPEARS.
# On a machine without `jsonschema`, `corpus.py check` never runs at all, and a
# reader who has not read the source would reasonably conclude the corpus is
# unverified rather than un-runnable. That is the wrong conclusion, and it is the
# reason this file is pinned rather than left as a note in a README.
#
# WHAT IS NEEDED, AND WHERE IT IS USED
# ------------------------------------
#   jsonschema   corpus.py          - `validate` and `check` validate every one
#                                     of the 321 records against its schema in
#                                     docs/artifacts/schemas/*.schema.json.
#   jsonschema   make_review_packets.py - section 5.1 of every review packet
#                                     reports whether the record is schema-valid,
#                                     re-derived independently of corpus.py.
#   referencing  both              - a transitive dependency of jsonschema, but
#                                     the corpus schemas use relative `$ref`
#                                     (`./artifact-base.schema.json`), which
#                                     jsonschema resolves only through a
#                                     `referencing.Registry`. Both corpus.py and
#                                     make_review_packets.py import it explicitly
#                                     and both fall back to a registry-less
#                                     validator without it, which silently drops
#                                     cross-file $ref resolution. It is pinned
#                                     here so that fallback is not reached by
#                                     accident.
#
# `referencing` was resolved at 0.35.1 in the environment these packets were
# generated in; jsonschema 4.25.1. The jsonschema floor below is the version
# from which `referencing` is a declared dependency, and is deliberately loose:
# the corpus uses no jsonschema feature newer than Draft 2020-12 validation.
#
# INSTALL
# -------
# THE REPRODUCIBLE COMMAND, for the interpreter running the corpus:
#
#   python3 -m pip install -r docs/artifacts/tools/requirements.txt
#
# On a macOS- or Debian-managed Python (PEP 668) that refuses with
# `error: externally-managed-environment`. The supported way past it is:
#
#   python3 -m pip install --user --break-system-packages -r docs/artifacts/tools/requirements.txt
#
# ...or, better, install nothing into the system interpreter at all:
#
#   docs/artifacts/tools/bootstrap.sh
#
# which creates a virtualenv OUTSIDE this repository (default
# ~/.cache/foxbms-corpus-venv, override with FOXBMS_CORPUS_VENV), installs these
# pins into it, and prints the command to run the suite with it. It creates
# nothing inside the tree and refuses to run if FOXBMS_CORPUS_VENV resolves
# inside it.
#
# Use `python3 -m pip`, never bare `pip3` or `pip`: a bare `pip` may belong to a
# different interpreter than the one running the corpus, and installing into the
# wrong site-packages is a failure that looks like success.
#
# WHY A VIRTUALENV IS OFFERED ALONGSIDE `--user`, and not instead of it
# -------------------------------------------------------------------
# `--user --break-system-packages` works and is printed by the preflight,
# because an operator who wants to install into their own user site-packages
# should be able to. But it mutates a shared interpreter that other projects
# also import, and `--break-system-packages` is a flag whose name is a warning.
# The virtualenv contains exactly the distributions declared here, cannot be
# broken by an upgrade elsewhere, and is removed with `rm -rf` on one directory
# in a cache.
#
# PINNING IS NOT INSTALLING - and that is why this recurred
# -------------------------------------------------------
# The pin below is a statement in a file. Whether an interpreter has the
# distribution is a fact on that interpreter's disk. Nothing reconciles the two,
# and a pin that has been sitting in the repository for months satisfies the
# reader while the suite is un-runnable. Measured, not hypothesised: this
# dependency went missing three times, with a DIFFERENT failure mode each time -
# once silently, with `corpus.py` exiting 0 having validated nothing; once as a
# `pip3 install --user` refusal with `externally-managed-environment`; and once
# as a failure whose message named a command that does not work on that
# interpreter. A version range cannot fix any of those. Run bootstrap.sh on a
# fresh checkout or after a restart, and confirm with the import below, before
# reading anything into the corpus's status.
#
# `--user` rather than a virtualenv by default because the corpus tooling is
# documented and invoked as `python3 docs/artifacts/tools/corpus.py ...` against
# the SYSTEM interpreter. If you use a virtualenv instead, install it there and
# invoke that interpreter; nothing in the tooling hardcodes `python3` except the
# self-test that shells out to the packet generator, and that uses
# `sys.executable`, so it follows whatever interpreter is running the suite.
#
# Verify with:
#
#   python3 -c "import jsonschema, referencing; print(jsonschema.__version__)"
#   python3 docs/artifacts/tools/corpus.py check
#
# A second, unrelated prerequisite - `git-lfs` - is required for the clean
# checkout proof and is NOT installable from this file. See
# docs/artifacts/governance/closing-list.md, "Prerequisites".

jsonschema>=4.18
referencing>=0.30
