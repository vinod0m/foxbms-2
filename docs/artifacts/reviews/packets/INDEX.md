# Review packets - index

Generated by `docs/artifacts/tools/make_review_packets.py`. 321 packet(s).

**Every packet in this tree is unsigned and contains no decision.** Each one ends in an empty signature block. No automated process fills it. If you find a filled block in a file here, that file was not produced by the generator.

A packet exists so a reviewer signs rather than reconstructs. Read `docs/artifacts/governance/closing-list.md` for who should sign what, in what order, and what they return.

## How to use one

1. Open the packet for your record. It embeds the record verbatim, so you need no other file open.
2. Section 5 tells you what is already machine-checked and what a peer already concluded. Do not redo section 5.
3. Section 7 has the questions only you can answer. For most records that is 2-4 questions, not a checklist.
4. Section 9 is empty. Answer section 7, then fill section 9 in your own copy.
5. Return the signed packet. Do not write the decision into the generator's tree - regeneration overwrites it, and the generator refuses to overwrite a signed packet rather than lose your signature.

## What a packet is checked against

- the record's own sha256, so a signature provably refers to the bytes hashed, not to a later revision;
- the corpus provenance gate's anchor classes: file existence, `content_hash`, `line_range` bounds, `symbol` occurrence, and evidence-log existence and hash;
- the `reviewed_ids` / `reviewed_by` coverage, with each review's digest state reported;
- every path the packet names, which `--verify` re-checks.

## Staleness

```
python3 docs/artifacts/tools/make_review_packets.py --verify
```

re-reads every packet and reports whether its embedded record bytes and digest still match the file on disk. `corpus.py check` runs the same verification as a non-fatal line, so a stale packet cannot go unnoticed for long. A stale packet is not an error in the corpus; it is a packet that no longer describes the record, and regenerating it is the fix.
