# Synthetic fixture evidence — NOT CAPTURED

**This directory is intentionally empty of fixture artefacts. That is a recorded
evidence gap, not an oversight.** This file documents exactly what is missing, which
records depend on it, and what would be required to regenerate it.

This file was written by hand. It is **not** generated by
`docs/artifacts/tools/corpus.py`, it is **not** test evidence, and it must never be
counted as captured evidence for any test. It is a statement about the absence of
evidence.

## 2. Why the fixtures are not reproduced here

The fixtures **cannot be legitimately reconstructed**, because no fixture content is
recoverable from anything the corpus retains. The specific blockers:

1. **The recorded digests are a single constant, not content hashes.** All three
   distinct purposes in all six records — the stdout log, the `input_hashes.test_source`
   digest, and the `input_hashes.config` digest — carry the identical value
   `sha256:339004f08d538371540704e160c5195bf5eb89e94fb22727c8faf9dca70f8a4e`.
   That is **18 uses of one digest across 6 records**. A captured log, a test source
   file, and a build configuration are three unrelated artefacts; they cannot share a
   content hash. The value is a placeholder that was never computed from any content,
   so no reconstructed fixture can be made to match it.
2. **The referenced log directory does not exist.** `build/synthetic/` is absent from
   the repository, and no directory anywhere in the tree is named `synthetic`. The
   per-record log paths therefore resolve to nothing.
3. **The environment is unrunnable as described.** Every record claims
   `x86_64 Linux host (simulated)` with `gcc 11.4.0`, `cmake 3.22.1`, `unity 2.5.2`,
   `cmock 2.4.0`. No such host or toolchain was ever provisioned, and the timestamps
   are the identical constant window `2026-09-13T00:00:00Z` → `2026-09-13T00:00:05Z`
   across all six records.
4. **Two of the six records name no test source at all** (`FB2-VER-EXE-000004`,
   `FB2-VER-EXE-000006`), so even the nominal input is unspecified.

Writing plausible-looking fixture files here would convert a *known, recorded* gap into
a *hidden* one. A file sitting in an evidence directory is read as captured evidence; a
fabricated one would be worse than an empty directory, because it would be trusted.

**No fixture was fabricated. This is the honest outcome.**

## 3. Correct interpretation of these six records

Read `outcome: pass` on these six records as **"a fixture was described, not
demonstrated"** — not as a captured result. Until this directory holds real fixture
artefacts whose digests match the records, these six records carry **no verification
weight of any kind**.

Note that the classification labels themselves are honest. `synthetic_fixture` does not
claim a target-hardware run, and the records do not claim product verification credit
(`product_verification_credit: false`). The defect is that the evidence *fields behind*
the `pass` are unbacked, not that the labels misdescribe themselves.

## 5. What would be required to close this gap

To make these six records substantiated, all of the following would be needed. None of
it can be produced retrospectively, because the original run left no artefact behind:

1. **Re-run the six measures against a real, provisioned host** with a toolchain whose
   versions are actually recorded rather than asserted.
2. **Capture per-run logs** into this directory, one file per execution record, with a
   **distinct** SHA-256 per file.
3. **Compute and record genuine input hashes** — the real digest of the test source and
   of the build configuration actually used, which will differ from each other and
   from the log digest.
4. **Record real start/end timestamps and duration** from the run, not a constant window.
5. **Update the six execution records** to reference the captured paths and the newly
   computed digests, and to state their `execution_kind` truthfully.
6. **Re-run the corpus validation and review gates** afterwards, because changing an
   execution record's evidence fields invalidates the review that covered its digest.

Until every step above is done for a given record, its `pass` is a description, not
evidence.
